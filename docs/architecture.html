Factory Inventory Management System

Architecture overview: a Vue 3 single-page app talks to a FastAPI backend over JSON/HTTP. The backend serves data loaded once from JSON files into memory. There is no database and no authentication.

1. System architecture

Browser

User's machine
  • Vue 3 SPA rendered client-side
  • Vue Router (HTML5 history)
  • Custom SVG charts, CSS Grid layouts
HTTP GET/POST
JSON
axios

Frontend dev server

Vite, port 3000
  • Serves the SPA and hot-reloads on change
  • Compiles .vue files via @vitejs/plugin-vue
  • Production build: npm run build
 
 

Backend API

FastAPI + Uvicorn, port 8001
  • Query-param filtering in Python
  • Pydantic response models
  • Auto docs at /docs

Data layer

Process memory, loaded at server startup
  • server/data/*.json read by server/mock_data.py into module-level Python lists and dicts
  • Changes made through the API are not persisted; restarting the server reloads the files

The browser calls the API directly at http://localhost:8001/api. The frontend server only serves static assets and does not proxy API calls.

3. Code layout

Frontend: client/src/

  • main.js registers the router and the six routes
  • App.vue holds the top navigation, the filter bar, and the profile and tasks modals
  • views/ one page per route: Dashboard, Inventory, Orders, Spending, Demand, Reports (plus Backlog)
  • components/ filter bar, navigation menus, detail modals, tasks modal
  • composables/ shared state: useFilters, useAuth, useI18n
  • locales/ English and Japanese strings
  • api.js the single place where backend URLs are built

Backend: server/

  • main.py the FastAPI app: models, filter helpers, and all endpoints
  • mock_data.py loads each JSON file once at import time
  • data/ seven JSON datasets (inventory, orders, demand, backlog, spending, transactions, purchase orders)
  • generate_data.py script that produces the sample data

5. Data flow: changing a filter

Example: the user picks a warehouse on the Dashboard.

  1. The user selects a value in the filter bar. The filter state lives in module-level refs in useFilters.js, so every page sees the same selection. client/src/components/FilterBar.vue, client/src/composables/useFilters.js
  2. The view watches the filter refs and reloads its data. client/src/views/Dashboard.vue
  3. The view calls an api.js method with the filter object. The method skips any value equal to all and builds a query string with URLSearchParams. client/src/api.js
  4. axios sends the request to FastAPI, for example GET /api/dashboard/summary?warehouse=.... http://localhost:8001/api
  5. FastAPI maps query parameters onto the endpoint arguments. Each endpoint runs apply_filters (warehouse, category, status) and filter_by_month (YYYY-MM or quarter) over an in-memory list. Filters always work on copies, so the loaded data is never changed. server/main.py
  6. The endpoint computes summary values, such as inventory value, low-stock count, and pending orders, and returns them as JSON. List endpoints are validated against a Pydantic response_model. server/main.py
  7. The view stores the response in a ref, and computed properties derive what the template shows. Components render the result with v-for keyed by a unique field such as sku, id, or month. client/src/views/*.vue

7. Observations and known gaps

Findings from reading the code. These were checked against the running server where noted.

  • Missing endpoints The client calls /api/tasks (GET, POST, PATCH, DELETE) and /api/purchase-orders (POST, GET), but main.py defines neither. A live check returned 404 for /api/tasks. The task calls in App.vue catch the error and only log it to the console, so the tasks modal looks like it works but nothing is saved.
  • Hard-coded URLs api.js and Reports.vue both hard-code http://localhost:8001. Changing the backend port or host means editing several files.
  • Reports bypasses api.js Reports.vue calls axios directly for its two endpoints, which breaks the single-client pattern.
  • Permissive CORS The backend allows all origins with credentials. This is acceptable for local development but must be restricted for any deployment.
  • No persistence Data changes exist only in memory. Restarting the server resets everything to the JSON files.
  • No authentication The current user in useAuth.js is a hard-coded mock profile with mock tasks.
  • Filter logic is centralised Filter helpers in main.py are shared across endpoints, and the frontend filter state is a single shared composable. These are the two places to change when adding a new filter.
